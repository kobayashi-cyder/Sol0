# Android 17 実機検証：安全な事前確認と実行記録

**状態：端末接続・実機試験は未実施。** このチェックリストはIssue #9の残作業を確定するためのものです。GitHub ActionsのAndroid15/Android17エミュレータ実行は、物理端末の代わりにはなりません。

## 1. 物理端末で読み取り専用チェック

専用テスト端末、データのバックアップ、PCのADB、Sol0の署名検査済みdebug APKを用意します。シリアル番号はGitHub IssueやCIログに貼らないでください。個人用端末ではなく、テスト用データだけを使用します。

~~~sh
adb devices -l

# 接続端末のシリアル番号をローカル環境変数に設定（公開しない）
export SOL0_TEST_SERIAL='端末のシリアル番号'
python android/tests/physical_preflight.py \
  --serial="$SOL0_TEST_SERIAL" \
  --apk=android-apk/app-debug.apk \
  --report=/tmp/sol0-android17-preflight.json
~~~

--apk を省略しても確認できますが、ローカルAPKのSHA256は記録されません。--reportは新しいファイルだけを作り、既存レポートを上書きしません。レポートは端末のシリアル番号・チャット内容・ログを含みません。

このツールは読み取り専用ADBコマンドだけを使います：adb devices、getprop、pm path、dumpsys package、cmd webviewupdate。アプリ起動・インストール・アンインストール・ログ取得・ファイル読み出しは行いません。Android API 37以上、非エミュレータ、Sol0パッケージ導入済み、WebViewプロバイダー検出、INTERNET権限の不在を条件として判定します。

**注意：** readOnlyPreflightReady が true でも、IME/長文履歴/画像生成などの実機テストは未実施です。ローカルAPKのSHA256一致も、端末へ導入済みのAPKが同一バイト列であることまでは保証しません。

## 2. APK導入（明示的な手動操作）

事前バックアップを確認した後にのみ操作します。debugビルドの署名鍵はCI環境ごとに異なることがあります。adb install -r が署名不一致で失敗した場合、自動でアプリを削除・clearしてはいけません。既存の会話データを失うおそれがあります。専用端末でのアプリデータの退避と署名の継続性を先に確認してください。

導入後、上記読み取り専用チェックを再実行します。

## 3. 物理端末で手動実行する項目

| 項目 | 実施と合格条件 |
|---|---|
| 日本語IME | 変換確定が送信扱いにならないこと。Enter改行、Ctrl+Enter明示送信の仕様どおり動くこと |
| オフライン | 機内モードでWSP学習・チャット・タスクが動作。APKにINTERNET権限がないこと |
| 長文履歴 | 3200文字を超えるassistantコードのJSONエクスポート・復元・アプリ再起動後に末尾まで保持 |
| 復元保護 | 壊れたWSP、容量超過、非対応schemaが既存の会話・資料・重みを置換しない |
| 画像・音声・動画 | PNG、WAV、GIF最大8秒、WebMを生成しファイルの再生/閲覧まで確認 |
| バックアップ・メディア | JSONとZIP、IndexedDBの復帰と再起動後の一貫性 |
| クラッシュ | WebView/Androidで重大な例外がないこと。個人情報を含むログは外部公開しない |

判定をIssue #9に記録するときは、端末名（型番）、APIレベル、WebViewバージョン、APKのSHA256、各項目の成功/失敗だけを記載してください。失敗した項目と再現条件を明示し、シリアル番号・個人情報・チャット内容は添付しないでください。
